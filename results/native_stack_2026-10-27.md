# 产品级（原生栈）模型评测报告

**日期**：2026-10-27 ｜ **口径**：原生栈（rime.dll + Go 管线，无 GUI）
**协议**：`docs/protocol_native_stack.md`（语料/按键/工具全部冻结并带 hash）

## 一、先纠正一个错误结论

2026-10-27 晚，我基于**引擎白盒**（直接调 rime.dll，绕过 Go 层）给出的结论
"万象整句只有 52.5、自训 wiki 模型最好、模型越大越差"——**是错的**。

引擎白盒测的是"librime 裸解码"，产品真实表现还包含 Go 层的上下文连贯、候选重排、
词典后处理。两者在 zhihu120 上差 5~10 点，且**排序会被反转**。

| 配置 | 引擎白盒（错误口径） | **原生栈（产品口径）** |
|---|---|---|
| 无模型 | 55.00 | 54.17 |
| wiki(-6) | 55.83 | 54.17 |
| essay(-4) | 55.00 | 58.33 |
| **万象(0)** | 52.50 | **63.33** |

万象在引擎层最低、在产品栈最高——这就是"每次会话结论都不一样"的根源：不同会话
混用了不同口径。

## 二、五档产品结论（原生栈，每臂两次复跑逐位一致）

| 臂 | top-1 | macroCER | Δ vs 无模型 |
|---|---|---|---|
| base（std/lite 无模型） | 54.17%（65/120） | 0.0983 | — |
| wiki（zh-moqi-wiki, -6） | 54.17%（65/120） | 0.0983 | **±0** |
| wiki（-14 长句档） | 54.17%（65/120） | 0.0983 | ±0 |
| essay（essay-bgw, -4） | 58.33%（70/120） | 0.0957 | +4.16 |
| **wanxiang（wanxiang-lts, 0）** | **63.33%（76/120）** | **0.0787** | **+9.16** |
| wanxiang（-6） | 63.33%（76/120） | 0.0787 | +9.16 |

- 万象在 0 与 -6 罚分下同分，说明该模型对罚分不敏感、鲁棒；
- 自训 wiki 模型在产品栈上**完全无增益**（0 / -14 都一样），与引擎白盒的 +0.83
  结论相反；
- essay 稳定 +4.16，与你们历史记录（+4.16）**精确吻合**，交叉验证了本协议可信。

## 三、结论与建议

1. **产品默认用万象模型**（+9.16，且体积 398MB 是可接受的"长句档"代价）；
2. **自训 wiki 模型不具备产品价值**——这推翻了我此前"用自训模型替代 essay/206MB"
   的建议。它在线下白盒里的微弱优势无法穿透 Go 层；
3. 若目标是"轻量档"：essay(206MB)=+4.16 是已验证的中间选项；wiki(64.5MB)=+0 不值得
   作为默认；
4. **口径纪律**（写进协议）：任何"产品表现"结论必须用原生栈或黑盒；引擎白盒只能
   用于引擎内部对比，且必须标注。

## 四、复现

```bat
rem 准备 data 目录 = 产品 stage 数据 + 一个 .gram + rime_frost.custom.yaml
scripts\bench_native_stack.bat <data_dir> <label>
```

runner 会自动用全新 user 目录跑两次，两次 `top-1`/`macroCER` 必须逐位相同；
不一致即视为环境不洁，结果作废。
