# 成绩单：墨奇引擎 vs 小狼毫引擎（8 格白盒矩阵，2026-10-26 晚）

**判决问题**：排除一切配置差异后，墨奇引擎（librime fork，1.6.1 产品 dll `7b799014`）
对比小狼毫引擎（0.17.4 `9975f25c`）还有没有存在必要。

**设计**：2 引擎 × 2 方案（明月 `luna_pinyin_simp` / 白霜 `rime_frost@328ded2`）×
2 模型条件（**无任何 gram**——白霜自带的 zh-moqi.gram 已删除、schema 组词惩罚按
"模型缺失"路径生效 / **+万象 gram** `wanxiang-lts-zh-hans.gram` sha256 `1849e5e4`）。
全白盒、零用户词库、读音 gold sidecar、**每格双轮**，整句 zhihu120（n=120）+
词级 words234（n=450）。frost 两目录 build 缓存已重置，杜绝旧模型残留。

## 二、性能与资源

- **解码耗时**（r2 热缓存）：明月 318/354 ms、霜 1295/1235 ms、明月+gram 369/416 ms、
  霜+gram 1397/1302 ms——差异 ±10% 内、无方向性，**无优劣**；
- **加载耗时**：本轮 build 缓存重建次序不同（小狼毫先跑吃了重建 4.6s），
  **不可比、不作结论**；
- **内存**（RSS 探针，含 gram 内存映射按需分页）：gram 增量两引擎均为 1~6MB 噪声级；
  墨奇基线 RSS 反而**高 8~10MB**（dll 大 330KB 及其代码量）。

## 三、判决

1. **解码维度：墨奇引擎与小狼毫引擎等价**——无模型逐格同分，挂模型 −0.83×2（噪声内）；
   速度无可证优势；内存略高。**以"引擎更强"为存在理由：不成立。**
2. 结合黑盒四臂（墨奇成品 62.50 vs 小狼毫同配置 65.83）与白盒引擎 A/B，
   三层受控证据收敛到同一结论：**墨奇的全部可测优势来自默认打包（白霜系词库+默认挂
   万象 gram），引擎与定制层零净增益、小负倾向。**
3. 若继续项目，价值主张只剩非解码维度：开箱体验（+20.8 vs 小狼毫默认）、
   轻量常驻、overlay/AI/简拼功能面、方案可插拔维护权；以及唯一未开采的技术差异化
   路径——gram 组句算法与自研 zh-moqi 模型（当前 7MB 版默认未挂、本矩阵未测）。

**一句话成绩单：引擎打平、定制不加分、产品赢在打包——"比小狼毫更强"目前没有
任何数据支持，"和小狼毫一样好且更贴身"是当前证据允许的上限定位。**

## 附三：mixed_pair 重排终审（2026-10-27 凌晨，native 栈无 GUI A/B）

工具：eval-workspace/eval-sentences-v3.exe（-stack native vs ime，-noFastPath，
-data 含 zh-bigram.tsv 时 Go 重排生效）。**墨奇产品层第一个可测真优势**：

| 词对集（混拼=前词全拼+后词声母） | native | ime（Go 重排） | Δ |
|---|---|---|---|
| 高频 500 对 | 33.40% | 47.80% | **+14.4** |
| 高频 2000 对（标准卷） | 28.35% | 36.40% | **+8.1** |

- 收益随词对分布而变：高频搭配大赚、弱搭配随机词对回归；10-22"默认开"的真人

## 附四：mixed_pair 调参终审（2026-10-27 晨，净 user 扫参）

内置默认实为 PairRatio=999/PairFloor=300（"只换词表无据首名"语义）。
每轮净 user 目录重扫（userdb 学习是污染源，共享 user 会漂移 1.5+ 点）：

| 配置 | 标准 2000 对 top-1 | d3pairs225 top-1 |
|---|---|---|
| 产品默认（999/300） | 36.40% | 51.11% |
| 激进（1.6/30） | 37.95% | 41.33%（随机对大回归） |
| **推荐（1.6/300）** | **38.10%** | **51.11%（零回归）** |

**推荐配置**：`contextual_lift.json` → `{"bigram_rerank":{"pair_ratio":1.6,"pair_floor":300}}`
——同 floor 放宽 ratio 999→1.6（首名有据也可换，须 1.6 倍搭配优势），高频混拼
top-1 **+1.70**、随机词对零回归，帕累托严格优于默认。配置落点：产品
`%APPDATA%\Moqi\contextual_lift.json`（native 评测器里是 user-ime 目录树下）。

## 附五：mixed_pair 调参的条件依赖终版（2026-10-27 晨二）

补测 nm67 激活条件后，推荐**按版本条件化**（nm67 native 28.35=裸 native，证 native
栈不走 Go 补丁、gram 不生效）：

| 配置（混拼 2000 对 top-1 / d3pairs225） | std | d3 |
|---|---|---|
| 引擎直连（无 gram/无 Go 层） | 28.35 | **63.56** |
| Go 层+裸霜+默认 999/300 | 36.40 | 51.11 |
| Go 层+裸霜+**1.2/500** | **38.25** | 52.44 |
| Go 层+nm67+默认 999/300 | 36.65 | 50.67 |
| Go 层+nm67+1.2/500 | 36.45 | 50.22 |

**结论**：①Go 重排对混拼总价值 +8（36.4 vs 28.35）；②调参 1.2/500 的 +1.85 只在
**无 gram** 条件下存在，nm67 下归零甚至 −0.2（gram 已修正首名，重排交换变多余）；
③d3 随机对的 −12 回归来自 Go 栈本身（floor≥300 时与参数无关）。

**内置建议**：带 nm67 的版本维持默认 999/300 不动；lite/无 gram 版内置 1.2/500；
用户 %APPDATA%\Moqi\contextual_lift.json 永远可覆盖内置值。floor 刻度绑定
zh-bigram.tsv 证据表（换表必重标），ratio 增益与否绑定 gram 状态（换万象需重扫）。
