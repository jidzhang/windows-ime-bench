# 五档安装包：安装建议与依据

**日期**：2026-10-27 ｜ **口径**：原生栈（产品级，含 Go 层；见 `docs/protocol_native_stack.md`）
**每臂均用全新 user 目录**（同一目录连跑会因学习漂移 0.2~1.5 点）。

## 一、实测数据

| 档 | 安装包 | 内置模型 | 整句 zhihu120 | 混拼（500 对） |
|---|---|---|---|---|
| lite | 36MB | 无（无预编译词库） | 54.17% | 41.40% |
| **std** | 74MB | 无 | **54.17%** | **41.40%** |
| wiki | 124MB | zh-moqi-wiki（-6） | 54.17% | 41.40% |
| essay | 229MB | essay-bgw（-4） | **58.33%（+4.16）** | 38.20%（−3.20） |
| wanxiang | 382MB | wanxiang-lts（0） | **63.33%（+9.16）** | 31.80%（−9.60） |

置信区间：整句 n=120 → ±9；混拼 n=500 → ±4.4。终值均经过复跑核对
（整句两臂逐位一致；混拼重复差 ≤1 对）。

## 二、逐档建议

| 档 | 建议 | 依据 |
|---|---|---|
| **std（默认）** | **推荐给绝大多数用户** | 混拼最优（41.40%），且体积仅 74MB、开箱即用（词库预编译，首键不卡）。混拼是日常高频场景，此档在其上无任何损失。 |
| lite | 仅用于"极致小体积" | 与 std 解码完全同分（54.17/41.40），唯一差别是**不带预编译词库**，首跑需现场编译（约 20 秒）。用户不差那 38MB 时没有理由选它。 |
| wiki | **不建议保留为独立档** | 整句与混拼**双维度与无模型完全相同**（54.17 / 41.40），124MB 换 0 收益。自训模型的线下微弱优势无法穿透 Go 层（引擎白盒 +0.83 的结论已推翻）。若想保留"自训"叙事，可降级为可选下载而非默认档。 |
| essay | 推荐给**长句优先**用户 | +4.16 稳定（与历史记录精确吻合），混拼代价温和（−3.20）。229MB 是可接受的中间档。 |
| wanxiang | 推荐给**只在乎长句**的重度用户 | +9.16，全场第一；但混拼 −9.60，是五档里最伤混拼的。适合长文写作、连续整句输入为主的人群；不适合日常短句/混拼为主的人。 |

## 三、一句话版本（可直接写进下载页）

- **日常用 → std**（混拼最好、体积适中）
- **写长文 → wanxiang**（长句最强，代价是混拼变差）
- **中间选择 → essay**（长句 +4.16，混拼小幅下降）
- **极致小包 → lite**（同 std，只是首跑慢 20 秒）
- **wiki 档建议下架**（与无模型同分）

## 四、结论背后的方法（为什么这次可信）

1. **口径正确**：原生栈包含 Go 层（上下文连贯、候选重排、词典后处理），与此前
   引擎白盒差 5~10 点且排序会反转——此前多轮矛盾结论的根源就是混用口径；
2. **输入冻结**：`corpus/zhihu120.txt` + 审计读音 `.pin.tsv` + 生成并校验过的
   `.keys.tsv`，消除逐字推导歧义；
3. **工具冻结**：评测器/rime.dll/拼音表/bigram 证据表全部入库存档并带 sha256；
4. **可复现**：`scripts\bench_native_stack.bat <data_dir> <label>` 一条命令跑一臂，
   自动全新 user 目录 + 复跑校验；
5. **外部交叉验证**：essay 的 +4.16 与你们既有记录逐位吻合。

## 五、复现

```bat
rem 每臂准备 data 目录（产品 stage 数据 + 一个 .gram + rime_frost.custom.yaml）
scripts\bench_native_stack.bat <data_dir> std
scripts\bench_native_stack.bat <data_dir> wanxiang
```

混拼列用 burst 模式（`-burst tools\native_stack\zh-bigram.tsv -burstMode fragment
-input shengmu -stack ime -burstTopN 500`），同样每臂全新 user 目录。
